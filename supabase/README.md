لا تحفظ مفاتيح Supabase الخاصة أو `service_role` في Git أو داخل APK. يستخدم التطبيق لاحقًا المفتاح العام فقط من إعدادات البيئة.

## الهجرة المطبقة

تم تطبيق الهجرة الأولى مباشرة على المشروع عبر Supabase MCP:

```text
initial_aman_schema_and_rls
```

أنشأت الهجرة الجداول الأساسية للحسابات والشركات والباقات وطرق الدفع والأرقام وطلبات الحماية والحمايات وإعدادات المهام والمهام التشغيلية والإشعارات وسجل العمليات. كما فعّلت RLS وأنشأت سياسات أولية للعزل بين العميل والمدير.

## ملاحظات أمنية

أظهر فحص Supabase الحالي تحذيرًا واحدًا على الدالة `public.rls_auto_enable()` لأنها `SECURITY DEFINER` وقابلة للتنفيذ من الأدوار العامة. لا توجد هذه الدالة ضمن الهجرة الأولى؛ يجب مراجعتها قبل اعتبار قاعدة البيانات جاهزة للإنتاج.

يجب أيضًا مراجعة سياسات RPC واختبارها بمستخدم عميل ومستخدم مدير قبل بناء عمليات القبول والإكمال النهائية.

## الخطوة التالية

إنشاء مشروع Flutter وربطه بعنوان المشروع ومفتاحه العام، ثم اختبار التسجيل وإنشاء ملف `profiles` وقراءة بيانات العميل من قاعدة amansoon.

أضيفت لاحقًا هجرة `refresh_operational_task_statuses` لتحديث حالات المهام الزمنية عبر دالة محمية تتحقق من دور المدير، مع منح التنفيذ للمستخدم المصادق عليه فقط ومنع PUBLIC.

وتوسعت الدالة في هجرة `notify_task_status_changes` لإنشاء إشعارات المديرين للمهام القريبة والمتأخرة دون تكرار عند إعادة التشغيل.

تتضمن هجرة `harden_security_and_user_status` حماية تغيير دور وحالة المستخدم، وRPC إدارية لتغيير الحالة مع سجل تدقيق، وفهارس للمفاتيح الأجنبية. كما أزيلت صلاحية RPC العامة عن الدوال الداخلية `is_admin` و`rls_auto_enable` في هجرة `cleanup_security_definer_acl`.

يتطلب التشغيل التلقائي الكامل للجدولة تفعيل Scheduler/pg_cron أو Edge Function مجدولة؛ فحص المشروع الحالي لم يجد امتدادي `pg_cron` أو `pg_net`. إلى حين تفعيلهما، يمكن للمدير تشغيل تحديث الحالات من شاشة المهام. تنبيهات Supabase المتبقية الخاصة بدوال `SECURITY DEFINER` تخص RPC محمية يتعمد التطبيق استدعاءها، وكلها تتحقق من `is_admin()` أو من صلاحية العملية داخل المعاملة.
