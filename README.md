# AMAN | أمان

## حالة المستند

هذه الحزمة هي نقطة البداية الرسمية لتطوير تطبيق **AMAN | أمان**. أُعدّت لتكون قابلة للرفع إلى مستودع Git والعمل عليها من حساب أو بيئة أخرى دون فقدان فهم المنتج أو قراراته التقنية.

## فكرة المنتج

AMAN خدمة تشغيلية تساعد العميل على تقليل خطر فقدان أرقام الهاتف بسبب الخمول. يضيف العميل أرقامه، ويختار رقمًا وباقة حماية، ثم تراجع إدارة أمان الطلب. بعد القبول، ينشئ النظام حماية فعلية ومهام سداد تشغيلية دورية. ينفذ مدير أمان السداد خارج النظام وفق الآليات المتاحة، ثم يسجل إكمال المهمة داخل التطبيق، فينشئ النظام المهمة التالية وفق إعدادات شركة الاتصالات.

> أمان ليست شركة اتصالات، ولا تملك الأرقام أو تنقل ملكيتها، ولا تتصل مباشرة بأنظمة شركات الاتصالات. الخدمة لا تمثل ضمانًا مطلقًا لاستمرار الرقم؛ بل تعتمد على أنظمة شركة الاتصالات وإمكانية تنفيذ العمليات المطلوبة في مواعيدها.

## قرارات المرحلة الحالية

- التطبيق يتصل بقاعدة بيانات فعلية منذ بداية التطوير.
- لا توجد بيانات وهمية أو Mock API في المسارات التجارية.
- قاعدة البيانات هي مصدر الحقيقة الوحيد.
- الواجهة لا تعرض نجاحًا قبل نجاح العملية على الخادم وقاعدة البيانات.
- العميل يرى بياناته فقط.
- المدير يدير العمليات الإدارية والتشغيلية وفق صلاحياته.
- تبدأ البنية كتطبيق متكامل Modular Monolith، لا كـ Microservices.
- الواجهة عربية وRTL أولًا، مع إبقاء التصميم قابلًا لإضافة الإنجليزية لاحقًا.

## التقنيات المعتمدة مبدئيًا

| الطبقة | الاختيار |
|---|---|
| Frontend | Next.js + React + TypeScript |
| UI | Tailwind CSS + مكتبة مكونات متوافقة مع RTL |
| جلب البيانات | TanStack Query |
| النماذج | React Hook Form + Zod |
| Backend | NestJS + TypeScript |
| API | REST + OpenAPI |
| Database | PostgreSQL |
| ORM | Prisma |
| الوظائف الخلفية | Redis + BullMQ عند الحاجة التشغيلية |
| الاختبارات | Vitest/Jest + Playwright |
| الملفات | Object Storage متوافق مع S3 |

## كيف تستأنف العمل

1. اقرأ `docs/PRODUCT-SPEC.md` لفهم نطاق المنتج وقواعد الأعمال.
2. اقرأ `docs/ARCHITECTURE.md` لفهم البنية التقنية وحدود الوحدات.
3. اقرأ `docs/ROADMAP.md` لمعرفة المرحلة الحالية والخطوة التالية.
4. اقرأ `ops/DEVELOPMENT-HANDOFF.md` قبل تنفيذ أي تغيير.
5. لا تبدأ مرحلة جديدة قبل تحديث حالة المرحلة السابقة واختبارها.

## قاعدة التسليم بين الحسابات

كل حساب أو وكيل جديد يجب أن يبدأ بقراءة هذه الملفات، ثم يحدّث `docs/ROADMAP.md` و`ops/DEVELOPMENT-HANDOFF.md` بعد كل مرحلة مكتملة. يجب أن تُحفظ القرارات المهمة في `docs/DECISIONS.md` بدل تركها في المحادثة فقط.

## لا توجد أسرار في Git

يجب عدم رفع كلمات المرور أو مفاتيح API أو ملفات `.env`. استخدم `.env.example` بأسماء المتغيرات فقط، واحفظ القيم السرية في إعدادات البيئة الخاصة بالمستودع أو منصة النشر.

## الحالة الحالية

هذه الحزمة هي **خطة وهيكل تسليم قبل التنفيذ البرمجي**. لم يتم بعد ربطها بمستودع خارجي؛ بعد تزويد رابط المستودع وطريقة الوصول المصرح بها، تُرفع الملفات ويُنشأ أول Commit.
