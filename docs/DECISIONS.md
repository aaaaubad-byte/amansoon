# سجل قرارات التصميم

## ADR-001: قاعدة البيانات الفعلية منذ البداية

**الحالة:** معتمد.

يستخدم التطبيق PostgreSQL فعلية منذ أول مرحلة تجارية. يمنع استخدام البيانات الوهمية أو LocalStorage كمصدر للحالة التجارية. يسمح ذلك باختبار العزل والمعاملات وقواعد منع التكرار مبكرًا.

## ADR-002: Modular Monolith

**الحالة:** معتمد.

يبدأ Backend كتطبيق واحد مقسم إلى وحدات أعمال. لا تستخدم Microservices في مرحلة التأسيس لأن العمليات الحساسة تحتاج معاملات مترابطة، ولأن الحجم الأولي لا يبرر تعقيد التوزيع.

## ADR-003: REST API

**الحالة:** معتمد مبدئيًا.

يستخدم REST مع OpenAPI. العمليات الإجرائية مثل قبول الطلب وإكمال المهمة واضحة كمسارات مخصصة وقابلة للتدقيق.

## ADR-004: البيانات التاريخية Snapshots

**الحالة:** معتمد.

تحفظ قيم ومدة الباقة داخل الطلب والحماية، ويحفظ مبلغ المهمة داخل المهمة. لا تعتمد السجلات التاريخية على قراءة إعدادات حالية قابلة للتعديل.

## ADR-005: الدفع الخارجي

**الحالة:** معتمد للمرحلة الأولى.

يدفع العميل خارج النظام ويُدخل رقم المرجع لطلب الاشتراك. لا يطلب النظام رقم مرجع تشغيلي عند إكمال المدير للمهمة، ما لم يتغير القرار التجاري لاحقًا.

## ADR-006: أمان ليست شركة اتصالات

**الحالة:** معتمد.

لا يوجد في التصميم افتراض بتكامل مباشر مع شركات الاتصالات أو تحكم في ملكية الأرقام. يجب أن يظهر إخلاء المسؤولية في المواضع المناسبة.

## ADR-007: التوثيق داخل المستودع

**الحالة:** معتمد.

كل قرار مؤثر يوثق هنا. وكل مرحلة تسجل في خارطة الطريق ودليل التسليم، حتى يمكن نقل العمل بين الحسابات دون الاعتماد على سجل محادثة خارجي.

## ADR-008: Flutter APK مع Supabase

**الحالة:** معتمد.

يُبنى التطبيق بصيغة Android APK باستخدام Flutter، لأن واجهة العميل والمدير يجب أن تعمل من الهاتف. تستخدم Supabase الخطة المجانية مبدئيًا لتوفير قاعدة PostgreSQL مركزية ومصادقة وتخزين ملفات دون استضافة Backend منفصل في مرحلة البداية.

يستخدم التطبيق مفتاح العميل العام فقط. لا يوضع `service_role` key داخل APK. تفرض PostgreSQL سياسات Row Level Security، وتنفذ العمليات الحساسة عبر RPC محمية أو Edge Functions.

## قرارات تنتظر الحسم

- نوع بيانات تسجيل الدخول.
- OTP من عدمه.
- العملة ووحدات المدة.
- قاعدة إنشاء المهمة الأولى.
- تفاصيل الأدوار الإدارية.
- سياسة انتهاء الحماية.
- النموذج المحاسبي لمبلغ المهمة.
