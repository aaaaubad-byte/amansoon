# خارطة طريق تطوير AMAN

## طريقة قراءة الخطة

كل مرحلة لها مخرجات واضحة ومعايير قبول. لا تنتقل المرحلة إلى `مكتملة` إلا بعد تنفيذ المخرجات وتشغيل الاختبارات وتحديث سجل التسليم. إذا توقفت الحصة أو انتقل العمل إلى حساب آخر، يبدأ التنفيذ من أول مرحلة غير مكتملة.

## المرحلة 0: تهيئة المستودع والبيئة

**الهدف:** إنشاء أساس قابل للاستمرار.

المخرجات:

- مستودع Git منظم.
- مجلدان `frontend` و`backend`.
- ملفات `.env.example`.
- إعداد TypeScript وLint وFormatting.
- Docker Compose لقاعدة PostgreSQL محلية.
- توثيق تشغيل المشروع.
- أول Commit يضم هذه الخطة.

معيار القبول: يستطيع مطور جديد تشغيل الواجهة والخادم وقاعدة البيانات باتباع README فقط.

## المرحلة 1: قاعدة البيانات والمصادقة

المخرجات:

- Prisma schema وهجرات PostgreSQL.
- User وCustomer وAdmin role.
- تسجيل وإنشاء جلسة وتسجيل خروج.
- حماية مسارات العميل والمدير.
- Seed آمن لمدير تطوير فقط في البيئة المحلية.
- اختبارات العزل والصلاحيات.

معيار القبول: يمكن إنشاء عميل وتسجيل دخوله، ولا يستطيع العميل الوصول إلى مسار المدير أو بيانات عميل آخر.

## المرحلة 2: الشركات والأرقام والباقات وطرق الدفع

المخرجات:

- CRUD لشركات الاتصالات.
- CRUD للباقات مرتبطة بشركة واحدة.
- CRUD لطرق الدفع.
- إضافة العميل لأرقامه.
- منع تكرار الرقم.
- عرض الشركات والباقات الفعالة والظاهرة فقط للعميل.
- واجهات الإدارة والعميل لهذه الوظائف.

معيار القبول: لا يمكن اختيار باقة من شركة مختلفة، وتعطيل الباقة يمنع استخدامها في طلب جديد دون حذف السجل التاريخي.

## المرحلة 3: طلبات الحماية

المخرجات:

- معالج طلب حماية متعدد الخطوات.
- تخزين Snapshots للقيمة والمدة.
- إدخال رقم المرجع.
- قائمة العميل وتفاصيله.
- قائمة المدير ومراجعة الطلب.
- قبول ورفض مع سبب إلزامي.
- إشعارات أساسية.
- Audit Log.

معيار القبول: القبول ينشئ حماية ومهمة أولى في Transaction، والرفض لا ينشئ حماية أو مهمة.

## المرحلة 4: الحمايات

المخرجات:

- قائمة حمايات العميل.
- قائمة حمايات المدير.
- تفاصيل الحماية.
- حساب البداية والنهاية.
- تحديث حالة الرقم إلى محمي.
- منع حماية مكررة.
- عدم تأثر الحماية بتعديل الباقة لاحقًا.

معيار القبول: بيانات الحماية السابقة ثابتة تاريخيًا، والعلاقات صحيحة في قاعدة البيانات.

## المرحلة 5: إعدادات المهام والمهام التشغيلية

المخرجات:

- إعدادات مستقلة لكل شركة.
- تصنيفات وأنواع المهام.
- مبلغ المهمة وفترة التكرار وأيام التنبيه.
- إنشاء المهمة الأولى.
- أقسام قادمة وقريبة واليوم ومتأخرة ومكتملة وملغاة.
- إكمال المهمة.
- إنشاء المهمة التالية.
- منع الإكمال المكرر.

معيار القبول: إكمال المهمة ينشئ دورة تالية واحدة فقط وفق إعدادات شركة الحماية، ولا يستخدم إعدادات شركة أخرى.

## المرحلة 6: الجدولة والتنبيهات

المخرجات:

- Worker مستقل أو Scheduler.
- تحديث الحالات الزمنية.
- إشعارات المدير للمهام القريبة والمتأخرة.
- إشعارات العميل المرتبطة بالحماية وفق السياسة المعتمدة.
- حماية التكرار في Jobs.

معيار القبول: تشغيل Job أكثر من مرة لا ينشئ إشعارات أو مهام مكررة.

## المرحلة 7: الإعدادات والتقارير والتقوية

المخرجات:

- إعدادات النظام والحماية والإشعارات.
- لوحة مؤشرات المدير.
- تحسين البحث والتصفية.
- نسخ احتياطي ومراقبة أخطاء.
- مراجعة أمان وصلاحيات.
- اختبار E2E شامل.
- توثيق النشر والاسترجاع.

معيار القبول: يستطيع فريق آخر نشر نسخة Staging واستعادة قاعدة البيانات وفق وثائق المشروع.

## ترتيب الأولوية عند ضيق الوقت

إذا كانت الموارد محدودة، يكون الترتيب الإلزامي:

1. قاعدة البيانات والمصادقة.
2. الشركات والأرقام والباقات.
3. طلب الحماية والقبول والرفض.
4. الحمايات والمهمة الأولى.
5. إكمال المهمة والمهمة التالية.
6. سجل العمليات والصلاحيات.
7. الإشعارات والجدولة المحسنة.
8. التقارير والتحسينات المرئية.

## تعريف الإنجاز

تعد الميزة مكتملة فقط إذا كانت تعمل من الواجهة إلى قاعدة البيانات الفعلية، وتطبق الصلاحية، وتتعامل مع حالات الفشل، وتحتوي على اختبار مناسب، ولا تعرض نجاحًا وهميًا، ووُثقت في سجل التسليم.
