# دليل التسليم والاستمرارية

## الغرض

هذا الملف يمنع فقدان سياق المشروع عند انتهاء الحصة أو نقل المستودع إلى حساب آخر. يجب تحديثه في نهاية كل جلسة تنفيذية مؤثرة.

## الحالة الحالية

- نوع العمل: تخطيط وهيكلة قبل التنفيذ البرمجي.
- المستودع الخارجي: `https://github.com/aaaaubad-byte/amansoon`.
- الفرع الرئيسي: `main`.
- آخر Commit مرحّل: `7b42928`.
- آخر مرحلة مكتملة: ترحيل وثائق المشروع الأساسية.
- المرحلة التالية: المرحلة 0، تهيئة تطبيق Flutter وربطه بـ Supabase.
- آخر تغيير: اعتماد Flutter APK وSupabase كقاعدة مركزية.

## قواعد العمل

1. ابدأ بقراءة `README.md` ثم `docs/ROADMAP.md`.
2. افحص آخر Commit وملفات التغيير قبل التعديل.
3. نفذ مرحلة واحدة أو جزءًا صغيرًا قابلًا للاختبار.
4. شغّل الاختبارات بعد كل تغيير جوهري.
5. لا تضع أسرارًا في الملفات أو Git.
6. حدّث هذا الملف وسجل القرارات قبل إنهاء الجلسة.
7. أنشئ Commit واضحًا بعد كل وحدة مكتملة.
8. لا تعتبر الميزة مكتملة اعتمادًا على شكل الواجهة فقط؛ يجب اختبار اتصالها بقاعدة البيانات الفعلية.

## قالب تحديث الجلسة

انسخ القالب التالي في نهاية كل جلسة أو حدّث قسم الحالة:

```text
التاريخ:
الحساب/البيئة:
المرحلة:
ما تم إنجازه:
الملفات المهمة:
الاختبارات التي نجحت:
المشكلات المفتوحة:
القرار التالي:
الأسرار أو إعدادات البيئة المطلوبة دون قيم سرية:
```

## خطوات نقل المشروع إلى حساب آخر

1. اربط الحساب الجديد بالمستودع.
2. نفذ `git clone` أو افتح المشروع من المستودع.
3. اقرأ `README.md` و`docs/PRODUCT-SPEC.md` و`docs/ARCHITECTURE.md` و`docs/ROADMAP.md`.
4. اقرأ آخر تحديث في هذا الملف.
5. أنشئ `.env` محليًا اعتمادًا على `.env.example`، ولا تنسخ قيم الأسرار من Git.
6. اربط التطبيق بمشروع Supabase تطويري مصرح به.
7. شغّل هجرات SQL وسياسات RLS الخاصة بالبيئة فقط.
8. نفذ الاختبارات قبل استئناف التطوير.
9. أكمل من أول بند غير مكتمل في خارطة الطريق.

## سياسة Git

استخدم رسائل Commit تصف النتيجة، مثل:

```text
feat(auth): add customer registration
feat(protection): approve request transactionally
feat(tasks): complete task and create next cycle
fix(tasks): prevent duplicate cycle creation
chore(docs): update development handoff
```

يفضل استخدام فروع قصيرة مثل `feature/auth` و`feature/protection-requests` و`fix/task-idempotency`. لا تدمج تغييرًا تجاريًا حساسًا قبل الاختبارات.

## متغيرات البيئة المتوقعة

لا تضع قيمًا حقيقية هنا. أسماء المتغيرات الأولية المقترحة:

```text
SUPABASE_URL=
SUPABASE_ANON_KEY=
# لا تضع SUPABASE_SERVICE_ROLE_KEY داخل APK أو Git.
```

## خطة النسخ الاحتياطي

قبل أي هجرة كبيرة أو تغيير بيانات في Staging/Production، يجب أخذ نسخة احتياطية والتحقق من إمكانية استرجاعها. لا تنفذ تغييرات تدميرية على البيانات التاريخية؛ استخدم تعطيلًا منطقيًا أو هجرات تحفظ السجل.

## آخر نقطة استئناف

ابدأ بإنشاء مشروع Flutter، ثم إضافة حزمة Supabase وربطه بمشروع Supabase تطويري. بعد ذلك أنشئ أول هجرات SQL للجداول وسياسات RLS، ثم حدّث هذا الملف وسجل Commit.
